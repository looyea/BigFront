# ng-landscape 面试题精选

> 共 15 题。A 类=原理机制；B 类=实战排坑；C 类=横向对比；D 类=场景设计。Angular 定位、改版史与四框架选型视角的入口题组。

### 1. (C) 面试官问『React/Vue/Angular/Svelte 到底有什么本质区别』——不许答『语法不同』，给三条判据级的对比。

**来源**：转述自本关 §一暗赌注论与 §四定位表

三判据：① **责任边界**——Angular 是应用框架（编译器/DI/路由/表单/HTTP 同一供应商，版本联动），React 是 UI 库+自选拼装，Vue 渐进（核心小、官方配、可浅用），Svelte 把责任推给编译器（运行时近乎为零）；② **变化通知模型**——Angular（v21+）signals 精确通知+zoneless、React 重渲染+虚拟 DOM diff、Vue 编译优化+响应式混合、Svelte/Solid 编译期细粒度——14 包海关链的框架投影；③ **约束与自由的汇率**——Angular 用强约定换升级自动化（ng update）与团队一致性，React 用自由换生态爆炸与选型疲劳。说出『汇率』这个词并展开，这题就超出多数候选人。

### 2. (A) 为什么企业（银行/电信/大型 B 端）偏爱 Angular？给三条框架能力层面的理由，不许说『名气大』。

**来源**：转述自本关 §一主场论与 §四寿命轴

① **升级是产品化能力**：固定版本节奏+ng update 迁移脚手架+codelyzer 风格规则——『五年十万行还迁得动』在这家是流程，在其他家是赌注；② **DI+模块系统给了架构显式表达**：新人接手看 provider 树就知道依赖流向，不用考古 Context 手搓和 hooks 闭包链；③ **决策真空被框架填掉**：路由守卫、表单校验、HTTP 拦截、变更检测策略都有官方正字——团队规模>50 人时『少开会』本身就是钱。诚实补一句边界：这三条的收益随项目寿命与团队流动率增长——三个月外包 prototype 用 Angular 纯属自缚（这就是选型三轴里『寿命轴』的反面应用）。

### 3. (C) 有人说『Angular v17 之后像换了一个框架，学旧教程是负资产』——给一张『年代探针』速查表（至少四组新旧标志）。

**来源**：转述自本关 §二改版史与 quiz q8 探针题的展开版

探针四组：① 组织方式——NgModule/declarations/imports（v17 前默认）vs standalone+app.config providers；② 模板控制流——*ngIf/*ngFor+ng-template 语法（旧）vs @if/@for/@switch（v17 新稳定语法）；③ 组件 API——@Input/@Output 装饰器（旧正统）vs input()/output()/model() 信号函数（v17.2+ 逐步主推）；④ 拦截器——class implements HttpInterceptor（旧）vs 函数式 withInterceptors（v15+）；外加测试器：Karma/Jasmine（v20 前默认）vs Vitest（v21 默认）。加分判据：说得出『实验→预览→默认→stable』四级舞步所以同一特性不同年份教程说法矛盾（signals 在 v17/v18/v19/v20 各被教程叫过不同状态）——探针要配时间轴才不误伤。

### 4. (A) Ivy（v9）换编译器换掉了什么？用应用层视角讲三点，不需要 IR 细节。

**来源**：转述自本关 §二改版表第三行（应用层转述，不挖编译器源码）

① **局部编译回归**：ViewEngine 时代改一个组件要全量重编译，Ivy 恢复按文件增量——开发体验（构建/热更）直接受益；② **产物可摇树**：组件/指令/管道编译成 tree-shakable 的函数声明，没用到的从 bundle 里掉出去（对照 14 包 sig-size 的『摇树四环』，Ivy 是重写了 Angular 版的四环）；③ **模板指令的运行时模型简化**：*ngIf/*ngFor 编译产物变轻，后来 @if/@for 能做得更快、v22 的 Signal Forms/新控制流优化都长在这块地基上。一句话定性：Ivy 是『看不见的改版』但没它就没有后面几次看得见的改版——面试把这句话讲透即可，编译器内部结构属 13 包式深挖范畴、本包声明不挖。

### 5. (B) 你面试的公司主力栈是 Angular 14 + NgModule 老仓，问『你觉得该怎么升级到新版本』——给一条分阶段路线图与两处最容易翻车的点。

**来源**：转述自本关 §二债栏与 §四寿命轴的现实应用（迁移方法论呼应 sig-migrate）

路线图四段：① 先升到 v16/17（跨大版本用 ng update 逐级，别跳级——官方只保证逐级）；② 存量 NgModule 不拆迁：v17 起可 bootstrapModule→importProvidersFrom 桥接、组件可逐个加 standalone: true 脱离 declarations——**按 feature 切，不按页面切**；③ 模板语法走 codemod（ng generate @angular/core:control-flow 官方自动把 *ngIf 转 @if）——机器活别手干；④ 最后再评估 zoneless（provideZonelessChangeDetection+全量回归）与测试器迁移。两翻车点：把 zoneless 和业务升级捆一个 PR（黑魔法库不兼容时归因灾难，ng version-map 债栏的原话）、大版本跳级升（v14→v20 直接改 package.json 的『速成升』会把弃用警告攒成 v21 的爆破现场）。

### 6. (C) 14 包口诀『内置管本家』——Angular 的 signals 与 TC39 提案、Solid signals 的关系一句话各给一条。

**来源**：转述自本关 §三概览与 14 包 tc39-frameworks 的回收

三句：① 对提案——Angular signals 在提案还是草案时就独立实现、语义高度对齐（signal/computed/effect/untracked 同名同位）但从未采用提案代码本体；② 对 Solid——Angular 的粒度停在『组件级信号』，Solid 细到每个表达式——同词不同粒度；③ 对本家——v20 stable、v21 起 zoneless 以 signals 为通知基础，signals 在 Angular 不只是状态 API，是**变更检测换代的地基**。加分延伸：这就是 14 包『框架内置响应的合流趋势』里最重的一块多米诺——企业级框架把 signal 写进默认栈，等于给整个赛道盖章。

### 7. (D) 产品总监（非前端）问『我们新项目该不该用 Angular，团队全 React 背景』——给一页纸决策，不许出现『看情况』。

**来源**：转述自本关 §四三轴的向上沟通版

框架：先锁三个事实参数——项目预期寿命（≥5 年？）、五年内团队人员更替率（高？）、产品形态（重交互 B 端后台？内容站？移动优先？）。结论直给：**寿命短（<3 年）或形态是营销站/内容站→不用**，React 团队的迁移成本在短期项目里永远收不回；**寿命长+是后台+流动高→用，但要买三年账**：6-12 个月团队生产力下降期（DI/装饰器/新响应式心智）、外部顾问或内训预算、招聘口径切换（会 Angular 的人和会 React 的人两个池子）。第三行必须写：『学习成本大头不在框架在范式（RxJS+signals 双轨）』——对应 14 包两税链：选 Angular 是把『生态选型税』换成『范式学习税』，总监听到这句才算听懂了。

### 8. (B) `ng new` 出来的工程被同事吐槽『文件比 React 项目多一倍、概念多三倍』——逐条回应：哪些文件在干什么、值不值。

**来源**：转述自本关 §三概览的应用层组织与部署预告

逐层：angular.json（构建/预算/环境配置集中营——对照 React 那边分散在 craco/vite.config/tsconfig 三处）、tsconfig* 分层（strict 默认拉满是刻意的『约束换安全』）、src/app 的 standalone 组件+app.config（providers 树，15 关 DI 的地基）+routes（配置式路由 vs 文件路由两种范式）、main.ts 的 bootstrapApplication。『概念多』的部分承认：DI token/变更检测/守卫接口确实是新增学习面——但指出交换比：这些概念在 React 项目里以『库选择+团队约定』形式存在（用哪路由？状态怎么管？——每次都要吵），Angular 直接给答案，吵的时间省下来花在业务上。一句话总结：**React 的简单是『上手简单、决策复杂』，Angular 相反**——没有免费的复杂度。

### 9. (A) 为什么 Angular 能把『路由守卫、HTTP 拦截、变更检测策略』做成框架正字，而 React 长期只能是社区约定？

**来源**：转述自本关 §一『内置正字』论与 §四定位表的机制化追问（呼应 react-router-data、sig-auth）

根本因不在团队能力而在**所有权结构**：Angular 的路由/HTTP/编译器是同一个包集合，版本联动允许跨层 API 契约（守卫函数可以直接 inject 任何 provider——守卫与 DI 耦合，这在库分离的 React 里无法设计）；React 的『官方』只有运行时与 hooks 原语，路由/数据层分属不同维护者——把守卫做成正字等于要求 react-router 与 Suspense/并发渲染版本同步，生态结构上就不可能。第二因：**应用框架敢对『应用如何组织』立法**（单例服务、组件树有根有界），UI 库的哲学是中立于组织方式。加分句：这个差异正在被 React 生态的『事实标准漂移』侵蚀（React Router v7/Framework、Next 把守卫式数据加载做进框架）——库路线正在补框架课，14 包『合流趋势』的组织学版本。

### 10. (C) 把『全家桶』放到移动端/小程序语境检验：为什么 uni-app/Taro 这类国内主流跨端方案里没有 Angular 的位置？

**来源**：转述自本关 §四『主场』论的边界测试（呼应 mp-overview、mp-framework）

三因：① Angular 的运行时假设（DOM+zone/signals 通知+ViewContainerRef 结构指令）与小程序双线程架构（无 DOM、setData 通道）对不上——重编译适配层（@angular/pwa 解决不了这个）没人维护；② 全家桶哲学与『框架只做 UI、宿主能力各家平台自己包』的跨端需求方向相反——跨端要的是薄运行时+厚适配，Angular 是厚框架+官方宿主；③ 生态经济学：Angular 的官方配套策略意味着社区库分流少，跨端适配这种『官方不做、社区做』的活恰好落在它的空档。结论句：**全家桶的优势域是『一个 Web 平台内部』——跨出 Web，全家桶变成全家负重**——选型三轴里从没提的第四轴『目标平台数量』在此显形。

### 11. (B) 你在技术分享里说『Angular 的样板多是因为它把别处隐式的依赖写成了显式』——现场被要求举例证明，给三个。

**来源**：转述自本关 §一『约束』论的反直觉辩护（样板 vs 显式的经典辩题）

① provider 注册——React 项目里『这个 service 谁实例化、单例范围多大』散落在模块顶层 new/Context/全局变量三处，Angular 一个 providedIn 字段把生命周期写进类型；② 组件依赖声明——standalone imports 数组 vs React 的 import 自动全局可用（谁渲染进模板依赖谁，Angular 显式列出，模板可审计）；③ 路由数据契约——resolve+typed params 让『进这页需要什么数据』出现在路由配置里，React 常藏进组件 useEffect 的抓取链。三例合一句：**Angular 的样板是『别处藏在运行时里的决策』被提前抄写在代码面上的成本**——读的人烦，接手的人爽；判断这套汇率值不值，用的还是寿命轴。

### 12. (D) 给一个『老 AngularJS（1.x）+ 混合 Vue2 页面』的祖传系统做现代化评估：三条可行路线与各自触发条件。

**来源**：转述自本关 §二改版债栏与 §四团队偏好轴的组合应用（迁移剧本：呼应 sig-migrate、react-to-solid-migration）

路线一（重写单页）：新页面一律新栈（Angular 2+ 或 Vue3——取决于团队偏好轴投票），老 AngularJS 靠 upgrade 模块共存，按流量迁移——触发条件是业务还在增长（有新增页面）；路线二（整仓升级）：1.x → ngUpgrade → 逐步 Ivy 化再 v17 化——只适合 AngularJS 存量巨大且业务停增（没新页面给你练手就没渐进动力），ng update 帮不了 1.x 到 2+ 这段，纯人肉；路线三（体面退场）：承认这套 UI 该死了，围绕它重写为微前端或直接换采购——当『祖传系统承载的业务本身要重构』时技术迁移和业务迁移合并做反而省。评估要点写进方案：**AngularJS→Angular 2 不是版本升级是换框架**（改版史第一行的债，今天还在收利息）——谁再提『顺手升一下』先答这三条路线的触发条件。

### 13. (C) 2026 年『前端招聘市场』的传闻里 Angular 与 React 的份额差在缩小甚至局部反超（欧洲/金融/大厂海外），给一个数据解读框架防止以偏概全。

**来源**：转述自本关 §四招聘市场轴的批判性展开（本地化：市场事实以当年招聘平台统计为准）

三格审问：① **地域格**——份额结论分市场：美国 React 绝对主导、欧洲/中东企业 Angular 占比高、国内两端都小（Vue 挤中间），拿单一国家数据说全球必然错；② **存量/增量格**——岗位数≈存量系统维护需求，新公司选型声量≠岗位数（『讨论度第一』的框架常是 React，『十年老后台还在跑』的常是 Angular）；③ **样本格**——培训班与自媒体放大的都是增量故事。落到个人决策：**你投简历的城市 × 目标行业 × 存量系统年龄**三个参数查表比任何趋势文章可靠——顺带自问寿命轴：愿意花五六年守一个系统的工程师，Angular 岗位的心智匹配度天然高。

### 14. (A) §三说『signals 在 Angular 是变更检测换代的地基』——用 100 字预演 L4 要展开的机制（提示：zone 拦截 vs 信号通知）。

**来源**：转述自本关 §三概览与其向 ng-zoneless 的桥接段（机制细节以 L4 为准，此处只立论）

旧模型：zone.js 劫持 setTimeout/Promise/DOM 事件，任何异步完成→全局脏检查整棵组件树——粗但全能；新模型：signal 写→computed/绑定订阅者精确重算，模板绑定本身就是订阅者——不需要『有人告诉我有异步发生了』，因为值变了自己知道。**从『事件驱动的重查』换成『数据驱动的直达』**——zoneless 不是删掉一个库，是把变更检测的触发权从运行时收回给数据层。一句话预告：这个换代在 React 那边对应『编译器自动 memo 化』的同一问题域，14 包两税链的『通知税』在 Angular 的解法。

### 15. (D) 面试官最后问『学完我们这个包（暗指你简历上的 15-angular），用一句话说 Angular 最大的代价』——三个候选回答各给一句，再选你的。

**来源**：转述自本关全篇立场的终极压缩（课程自我答辩题，呼应 sig-roadmap q15 同型）

三候选：①『心智前置』——写 Hello World 前要先接受 DI/装饰器/模板编译/变更检测四个概念区，渐进性输给 Vue；②『范式时差』——本包最大的暗成本：旧知识保质期短（v14 学到的 NgModule 姿势今天已是债务），五年里你其实是在『学两个框架』；③『反生态引力』——框架答了所有选择题，也关掉了所有选项（想用某个 React 生态件？写适配自己搬）。我的选择：② 最贵但可治理（版本地图关+官方迁移脚手架就是它的解药），① 最疼但一次性，③ 最隐蔽但因人而异——把代价排进『可治理/一次性/结构性』三档，正是这包 L1 想训练的选型思维：**评价一个框架的代价，先给代价分类，再谈大小**。
