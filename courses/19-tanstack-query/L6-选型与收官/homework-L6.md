# L6 阶段作业：选型与收官

最后一关不写新功能代码——做对比、画地图、交毕业项目。三关作业一次完成，交付物是「决策文档 + 能跑的数据层」。

## 一、知识回顾

1. 写出状态四层与各自判据（「数据归谁」四分法），每层举一个你项目里的真实例子。
2. Query 相对 SWR 的四个「出现即迁移」信号是什么？
3. 背出毕业项目自查清单的三大类（结构/行为/工程）各两条。

## 二、代码实操

**实操 1（选型报告）**：给同一需求（列表+搜索+提交刷新）各写 Query 与 SWR 两版实现，交 300 字对比：代码行数、概念数、你会选谁及理由——禁止用「更流行」当理由。
**实操 2（分层审计）**：打开你手头任意在用项目（或本课程的 todo/feed 练习），画状态分层图：store 每个字段、Query 每条 key 对号入座；找出至少 1 处反模式并完成搬迁，删除对应的 useEffect 同步链，行为回归验证。
**实操 3（毕业项目）**：按 tq-capstone 清单完成影视浏览数据层全链（SSR 可后置为挑战项），交付 README 一页「数据层设计说明」（key 树/默认值理由/失效矩阵/覆盖范围/测试策略五段）。

## 三、思考题

1. 「Query 也能管 client state（setQueryData 不就完了）」这个说法错在哪？用双份真相论证。
2. 毕业项目里如果收藏接口幂等（重复调用结果相同），乐观更新的回滚逻辑可以简化掉哪一步？
3. 四层里最容易被忽视的是哪层？结合自己的 bug 史谈（多半是 URL 态）。

## 四、延伸阅读

- 官方 Comparison 页逐行精读（/comparison），给每行找一个自己的真实案例
- TanStack 全家福：Router / Table / Virtual / Form 的 overview 各览一遍，标出与本课四层的接口点
- SWR 官方文档 Getting Started + Advanced 对读（自建判断，别听转述）
- 回顾线：16-pinia 的 overview、17-zustand 的 layers、18-jotai 的 race/capstone 四篇串读——毕业感言的素材库

## 五、自查清单

- [ ] 分层图与审计报告完成，至少一处反模式已搬迁并回归
- [ ] 两版选型实现可运行，对比报告有数字有结论
- [ ] 毕业项目：key 工厂 / 无 useEffect 拷数据 / queryFn 全收信号 三条结构项达标
- [ ] 行为项：返回不闪、点进秒出、离线排队、多标签同步 四项至少三项亲眼验证
- [ ] 工程项：SSR 首帧无重复请求、persist 白名单、失败回滚有测试
- [ ] README 设计说明五段齐全，能顶住一场 30 分钟的数据层面试
