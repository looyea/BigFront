# L8 阶段作业：架构与集成

> 覆盖：sig-server / sig-migrate / sig-auth
> 判分：Bug 每题 3 分、手写每题 7 分、场景题 20 分、简答每题 5 分、挑战 +10 分（基分 100）

## 一、Bug 猎杀（10 小题，每题指出唯一错误并给出修法）

**Bug 1**（图书馆的书进传家宝柜）
某 store 初始 state 含 `articles: []`，组件 `useEffect` 拉取后 `setArticles(res)`。用 sig-server q11 三问审计该字段，给出三个问题的答案与迁移结论。

**Bug 2**（失效=删除）
团队手搓的 `refreshArticles()` 先 `set({articles: []})` 再发请求，用户每次刷新全页闪骨架。指出失效语义错误，给『标脏』语义的两条实现路径（库版/手搓版各一）。

**Bug 3**（反向数据流）
搜索页把接口响应 `set({ filters: res.appliedFilters })`——用户发现筛选条件被服务器『改回去』了。违反边界协议第几条？正确的 key 写法是什么？

**Bug 4**（乐观更新站错队）
本地草稿功能用 `onMutate` 存快照、失败回滚——用户断网写了一半的草稿没了。按 §三协议 2 的『该不该退回』提问重新归属，给正确存放点。

**Bug 5**（登出半边天）
`logout()` 只写了 `localStorage.removeItem('token')`。列出它至少漏掉的三样清场对象，指出哪一样会造成『跨用户数据残留』级事故。

**Bug 6**（双向桥）
迁移期有人把双写桥写成：旧 subscribe 里 setState 新、新 subscribe 里 dispatch 旧。用三纪律判它违反了哪条，说明第一次双方同时触发时的具体现象。

**Bug 7**（桥上传行为）
桥代码：`useNewStore.getState().doSomething(action.payload)`——把旧 Redux 的 action 转成新 store 的同名方法调用。指出这是哪条纪律的哪个变体，事故形态与『过值』版修法。

**Bug 8**（跨库私聊）
MobX reaction 里 `uiStore.setState(...)`、Zustand subscribe 里又有 `domain.touch()`。画出这条通知环，指出 glitch 出现在哪个缝隙，给合规接口的三要素。

**Bug 9**（守卫里的 hook）
路由守卫函数里 `const t = useAuthStore().token`。双重错误是什么？给正确读法，并说明这种『旁路读』在组件渲染体里为什么反而成了滥用。

**Bug 10**（布尔两难闪现）
persist 恢复前 `user === null` 被守卫判为未登录，刷新页面闪一帧登录页。指出状态建模缺了什么，给三值化修法与另一条『乐观显示』路线。

## 二、手写题（5 题）

**手写 1**：给一个含 8 个字段的示例 store（user/theme/文章列表/草稿/页码/token/侧边栏/权限表）做完整三问审计，产出『字段 × 三问』表与迁移工单（哪些进 Query、哪些留 store、哪些拆两半）。

**手写 2**：把 §二 Zustand 版 auth store 改写为 MobX 版（RootStore 组装）与 Solid signals 版（模块级导出），各标注：守卫读法一行、登出联动一段、总行数——三版并排贴出。

**手写 3**：为双写桥写一个 50 行『reducer-of-states 对拍器』：输入=同一 action 序列+两个 store 初始态，输出=每步 diff 报告；用 3 个操作剧本跑通，故意在剧本 3 制造一次分叉让报告抓到。

**手写 4**：写『状态架构宪法』三条（数据归属/共享分级/跨边协议）的 lint 或 CI 检查方案：每条给可 grep 的违规模式示例与报错文案（无法全自动的注明『半自动+review 清单兜底』）。

**手写 5**：互踢功能四实现改造：在 Zustand 版 auth store 上加 `logout(reason)` 参数化单入口+BroadcastChannel 接收端；写 5 行说明为什么这个需求形状下 RxJS 版『几乎免费』。

## 三、场景题（1 题，20 分）

你入职一个 3 年老 React 项目：全部状态在自造『全局 store』（单例对象+手写发布订阅），接口数据/域逻辑/UI 态混装，最近连续出现『A 用户看到 B 用户残留数据』与『搜索页偶发旧结果覆盖新结果』两起事故。团队吵了三派：上 Redux / 上 MobX / 全迁 React Query。用 L8 三关的语言给完整方案：① 两起事故的归因（各对应本阶段哪个机制缺失）；② 对三派各给一句判词（用『Query 模型是思想不是那个包』与形状识别框架）；③ 分层目标架构（数据/客户端事实/域逻辑各归谁）；④ 分期迁移路线（含桥、flag、对拍、删行数验收）与『哪些现状可以永久保留』的判断；⑤ 一条防复发制度。要求每步注明引用了哪一关的哪个判据。

## 四、简答题（3 题）

**简答 1**：『组件从 useQuery 读和从 store 读一样短，但生命周期完全不同』——用『所有权』这个词把这句话讲透（150 字内）。

**简答 2**：迁移第一定律为什么说『没有一把梭重写这个选项』？给它的两个例外场景（什么情况下重写反而理性）。

**简答 3**：登录态四份答卷的锁定度为什么方向相反（锁库 vs 锁框架）？各用什么成本换来了什么收益？

## 五、挑战题 🏆（+10 分）

『登录态四胞胎』工程：把同一登录态需求（共享+守卫+登出清理+互踢）分别用 Zustand、MobX、Solid signals（或 preact signals+React）、RxJS BehaviorSubject 实现为四个可运行 demo，各写一条『守卫同步读』与『跨标签页登出』的 e2e 断言。交付对照报告：核心行数/隐形胶水行数分开统计（戳穿代码量骗人）、你更愿意维护哪个+三行理由、评分表外你发现的第五个维度（若有）。分项：四 demo 各 1 分共 4 + e2e 断言 2 + 报告 4。
