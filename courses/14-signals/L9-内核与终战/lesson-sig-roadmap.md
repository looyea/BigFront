# sig-roadmap：包复盘与进阶路线

> 目标：把 14 包收拢成一张可带走的地图：sig-map 定位图的期末版、四强各两个值得再深入的方向、与框架内置响应的合流趋势判断（signals 提案/服务端状态/细粒度化），最后交出一份结课自检清单——这条路线的终点不是『全学会』，是『知道下一步往哪走』（呼应 sig-map、全仓各包）

## 一、地图期末版：从定位图到判据链

sig-map 发的是『四强×坐标系』的静态图，学完全包后你手里换成三条动态判据链，图就活了：

1. **海关链**（管过程还是管状态）：过海关时事件变成状态——需要『补发/编排/时间轴』留在 RxJS 侧，需要『当前值/订阅面控制』走 signal 侧；
2. **两税链**（可变还是不可变）：可变付协作纪律税（MobX 的 action 面、可 grep 性差），不可变付语法学习税（Zustand 的 selector 设计、immer 心智）——没有免税范式，只有免税位置不同；
3. **五碗链**（谁管哪段）：RxJS 管过程、Query 管远端、MobX 管领域、Zustand 管共享、useState 管局部、内置管本家——决策树比冠军重要，capstone 的记分卡就是这句话的仪器版。

三条链共用一个底座：**读需求形状，再选决策代价**——本包九十个小时教的核心动词就这一个。

## 二、四强进阶：各两个方向，深水区地图

**TC39 Signals**：① 提案本体与 alpine/legendapp 等高性能实现的**版本号惰性机制**（internals q14 留的门：Fine-Grained Reactivity 论文是共同源头，读懂它≈读懂下一代调度器）；② 各框架的 signal 适配层写法（Angular signal 桥、Preact signal 库源码都只有几百行——internals 毕业后的第一个可读源码）。
**RxJS**：① **调度器与背压**（internals 关你只用了 forEach，RxJS 把 §三第 1、2 条做成了可插拔 Strategy）；② `@rxjs/observable` 之外的**可观测生态位转移**——AsyncGenerator 与 Observables 的竞合（『管过程』席位的新候选人，海关链的下一回合）。
**MobX**：① MobX 6 编译时方案与**属性级依赖图的生产调优**（internals q13 三层的完整版）；② 大型域模型项目的 store 演化治理（mobx-stores 关的架构线往 50 万行规模延伸：状态机化、跨模块契约）。
**Zustand**：① 中间件机制的**洋葱组合子**自己写一个（za-middleware 留的钩子：devtools 通道的复用）；② **vanilla store + 细粒度适配器**（`useSyncExternalStoreWithSelector` 的原理深读——理解 React 派订阅模型后，你看 Jotai/Redux/Zustand 是同一张图的三种投影）。

## 三、合流趋势：三条线正在交汇

1. **signals 提案**改变的是『库与框架的谈判地位』：库交出图元定义权、框架交出调度优化——L2 讲的『标准边界』若被填上，跨库迁移成本会先降后升（降于 API、升于生态位站队）；
2. **服务端状态上移**基本终局：Query 模型已是共识，争的只是寄宿在第三方库还是路由层（sig-server §四的『数据上移、职责同在』判断句按年复验）；
3. **细粒度化回潮**：React 官方对 signal 形态的暧昧（文档只字不提、useSyncExternalStore 却越用越多）、Vue Vapor/Solid 的存在证明虚拟 DOM diff 不是唯一答案——sig-size 说『先测量再吵架』，这条线上吵的正是『抽象税值不值』。

三线的交点：**状态管理的『库时代』在收缩，『协议时代』在展开**——未来五年更耐用的知识是海关链/两税链/五碗链这套判据，不是任何一家的 API 表面。
