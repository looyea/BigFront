# 调试、真机与上架

> 目标：本包最后一关，把"写完代码"到"用户能搜到并用上"的交付链走通：**调试工具链 → 体验版与提审 → 审核规范与驳回自救 → 发布与灰度回滚**。这是 09-express 的 exp-deploy、05-react 的 react-deploy 在微信世界的对应物——只是"部署"变成了"提审"，"回滚"变成了"版本回退+热修复红线"（呼应 **exp-deploy**、**react-deploy**、**mp-openapi** 合规）。

---

## 一、调试工具链（按场景选枪）

| 场景 | 工具 |
|---|---|
| 日常开发 | 开发者工具：模拟器 + **vConsole**（调试按钮开）+ Audits 体验评分 |
| 真机差异（渲染/性能/蓝牙） | **真机调试 2.0**（断点打在手机上跑、看真实日志与 Network） |
| 线上用户问题 | 小程序后台"**错误日志/实时日志**"（`wx.getRealtimeLogManager` 端上主动打）、**监控告警**（JS 异常率、启动失败率） |
| 自动化 | **miniprogram-automator**（SDK 驱动工具跑脚本，接 CI——你的 jest 技能平移，呼应 node-testing/exp-testing） |
| 接口层 | 工具 Network 面板 + request.js 的 traceId 贯穿前后端日志（呼应 exp-patterns） |

命令/CLI 侧：`miniprogram-ci` 支持**脚本化上传**（密钥对认证）——把"版本号+changelog+上传"接进 CI，别再手工点"上传"按钮（呼应 exp-deploy 流水线）。

## 二、发布流水线：开发版 → 体验版 → 提审 → 线上

```text
上传代码 ──→ 开发版（成员任意角色可玩）
  └─ 设为体验版 ──→ 体验者扫码验收（体验版可开"调试模式"看 vConsole）
        └─ 提交审核（填页面/类目/权限用途说明）
              ├─ 通过 → 发布（全量 / 分阶段发布=灰度）
              └─ 驳回 → 看驳回详情 → 整改 → 再审（可申诉）
线上版本可"回退"到上一稳定版；每次提审留 1~2 天缓冲（节假日更长）
```

三个角色别混：**开发者/体验者/管理员**（成员管理各管各的入口）；"分阶段发布"可按比例放量（灰度心智与 exp-deploy 的 canary 同构）。

提审前自查清单（血泪浓缩）：

- [ ] 所有域名已白名单且生产可用（真机体验版走正式域名！）——mp-network；
- [ ] 需权限的功能都有**用途说明弹窗/引导**且可拒绝可用——mp-openapi 声明文化；
- [ ] 隐私协议配齐、`__usePrivacyCheck__` 生效路径测过——mp-login 第四节；
- [ ] 无诱导分享/关注话术——mp-interaction 面试 10；
- [ ] 空态/断网/错误兜底齐全（审核员会点"未登录+无数据"路径）；
- [ ] 测试账号与备注写清（含支付沙箱路径），类目与实际功能一致。

## 三、审核驳回 TOP 原因与自救

| 驳回类型 | 典型触发 | 自救 |
|---|---|---|
| **功能不一致/类目不符** | 商城挂"工具"类目、页面出现未声明的交易 | 改类目或隐藏未过审模块（后台"分页面提审"策略）|
| **诱导分享/关注** | "分享后解锁""关注领券"弹窗 | 改文案与流程，奖励不绑定分享动作 |
| **权限过度申请** | 进首页就要定位+手机号 | 懒授权：触点才申请（mp-login 懒登录同理）|
| **体验问题** | 白屏/死链接/测试号不可用 | 提审前"审核路径"走查（给审核员专用引导）|
| **无资质** | 医疗/金融/内容类缺证件 | 补资质或砍功能——无捷径 |

被驳回可在"审核详情"看具体页面截图；误判可**申诉**（附录屏与功能说明）。原则：**驳回原因全部沉淀进自查清单，同一条不被拒两次**（呼应 exp-deploy 上线检查单、node-publish 发布清单）。

## 四、灰度、监控与回滚

1. **放量**：分阶段发布 10%→50%→100%，每档盯 JS 异常率/启动成功率/业务转化（后台运维中心+自建看板）；
2. **热修复边界**：小程序**没有**运行时改代码的后门（那是 App 的彩蛋），紧急问题=回退版本（一分钟内可回退到上一线上版）或"配置化开关"降级（服务端下发开关藏掉坏模块——架构上要为可降级设计，呼应 react-architecture、mp-cloud 的接缝论）；
3. **兼容矩阵**：基础库"最低版本"设置决定旧微信客户端行为——新功能页设最低版本并要求"提示升级"文案（后台可配）；
4. **多版本并存心智**：线上版/审核版/开发版/体验版是**四个隔离环境**，数据与域名策略要提前分档（呼应 mp-network 面试 2 的环境域名管理）。
