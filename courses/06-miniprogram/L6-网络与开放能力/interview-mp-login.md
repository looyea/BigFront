# mp-login 面试题精选

> 共 12 题，覆盖 A 登录链路 / B 身份与标识 / C 授权与隐私 / D 会话工程与安全。

## 一、登录链路（A 类）

### 1. 完整讲一遍小程序登录，为什么需要"code 中转"而不是直接给 openid？
wx.login→code（临时、一次性、5 分钟）→服务器 code2session(appid+secret+code)→openid/session_key→建/查用户→签发自有 token。code 中转的原因：code2session 必须带 **AppSecret**，而 AppSecret 只能在服务器持有；code 即使被截，5 分钟内一次性、且无 secret 换不了东西——典型的"凭证分级"设计（呼应 exp-auth 的 token 分级讨论）。
**来源**：微信小程序官方文档《登录》；OpenID Connect Authorization Code 流程对照

### 2. code2session 返回 40029 / 45011 / -1 分别怎么处理？
40029=无效 code（多半重复使用/过期→前端重走 wx.login）；45011=频率限制（风控，提示稍后再试+重试退避）；-1=系统繁忙（可幂等重试 1 次）。把微信错误码翻译成业务码再返回前端，是后端网关的基本职责（呼应 exp-validation 错误码映射）。
**来源**：微信小程序官方文档《登录凭证校验错误说明》

### 3. 为什么"登录"不必在小程序启动时强制做？
wx.login 静默无感，但**建账号+弹隐私**的成本应后置：浏览场景用游客态（openid 可延到首次写操作再换），转化数据更好；"启动即登录"在审核侧也愈发敏感（非必要不收集）。懒登录+触点登录是通行方案（呼应 mp-login 第五节、mp-lifecycle onLaunch）。
**来源**：微信运营规范《收集用户信息最小化原则》；社区转化实践

## 二、身份与标识（B 类）

### 4. openid / unionid / appid 三者关系？用户在三处数据如何归一？
appid 标识应用；openid=用户×appid 的指纹；unionid=用户×开放平台账号（同一主体绑到 open.weixin.qq.com 后，公众号/小程序/App 间归一）。数据库用 unionid（若有多端）做自然键、openid 做本端索引；只有 openid 的单端产品直接以它为用户主键映射（呼应 ts 课程主键设计类比、exp-rest 资源标识）。
**来源**：微信小程序官方文档《unionid 机制说明》

### 5. 能拿 openid 当"业务用户 ID"直接暴露给前端接口参数吗？
能暴露但不建议当主键使用：openid 无业务含义、不可变、跨系统不通；应内部 uid 对外，openid 只在登录环节出现。日志里 openid 也属敏感标识，展示需脱敏（呼应 exp-security 数据脱敏）。
**来源**：《小程序用户体系设计》实践帖；个人主体项目通用结论

## 三、授权与隐私（C 类）

### 6. wx.getUserProfile 还能用吗？这段历史怎么讲的？
2022-10 起返回匿名数据（灰条头像+"微信用户"昵称），官方推荐改用"填写昵称"组件+chooseAvatar，接口实质已废。讲解时分三代：getUserInfo（静默全给）→ getUserProfile（点击确认）→ 用户填写（表单化）——体现"平台回收默认授权"的合规趋势（呼应 mp-login 第三节）。
**来源**：微信官方公告《getUserProfile 接口调整》；开放社区迁移指南

### 7. 手机号授权为什么有主体门槛？旧版加密数据方案还有什么坑？
个人主体/未认证主体不能开通（防电诈滥用）。旧版 getPhoneNumber 回传 encryptedData+iv，需**当时那一轮的 session_key** 解密——session_key 会随重新登录刷新、与密文不匹配时报错（解密失败高频根因）；新版 code 直接调 `phonenumber.getuserphonenumber` 无此耦合，官方推荐迁移（呼应 mp-login 第三节表）。
**来源**：微信小程序官方文档《手机号快速验证组件》；解密失败案例社区精选

### 8. 哪些操作会触发"隐私接口需同意"？弹窗设计原则？
位置、相册/摄像头、麦克风、手机号、通讯录、剪贴板读取等均在《隐私保护指引》申报范围，未同意直接 fail（errno 103/相关告警）。原则：场景化触发（点"定位门店"才弹）、可拒绝可降级、拒绝后功能降级话术备好；"不同意就不给进 app"式捆绑已被驳回案例反复教育（呼应 mp-login 第四节、运营规范）。
**来源**：微信官方公告《小程序隐私协议开发指南》；审核驳回案例社区汇总

## 四、会话工程与安全（D 类）

### 9. 小程序端应该存什么、后端应该存什么？
端：自有 token（JWT 或 session id）、非敏感的展示缓存（昵称头像）；**不存** openid 明文到处传、session_key 绝不落地、手机号等 PII 尽量只存后端按需脱敏下发。后端：openid/unionid/手机号密文、session_key（内存态/短期缓存，且知道它会失效）。依据"泄露面最小"逐字段审（呼应 mp-storage、node-config 密钥管理）。
**来源**：微信小程序安全指南；OWASP Token 存储最佳实践对照

### 10. 有人伪造 token 怎么办？有人抓包重放 code 怎么办？
token：服务端验签（JWT secret 轮换）、过期短+refresh 机制、uid 与设备/风险分风控；code 重放：一次性+5 分钟即天然防重放窗口，后端消费 code 时记录"已用"更稳（db 唯一约束）。结论：微信链路只给"身份锚点"，防重放防伪造是自家常规（呼应 exp-auth 中间件、exp-security 限流）。
**来源**：微信小程序官方文档《登录流程安全说明》；JWT RFC 8725 实践

### 11. 多端（公众号 H5 + 小程序 + App）账号打通方案？
开放平台 unionid 为主键归一（需同一开放平台账号）；缺 unionid 时靠"手机号/账号密码"人工绑定流；登录后各端签发各自的 token、共享 uid 体系。架构上用户中心独立服务化，避免每端各写一份登录（呼应 react-architecture 边界、exp-patterns）。
**来源**：微信开放平台官方文档《unionid 机制》；多端账号体系设计实践

### 12. 灰产用"接码+群控"批量注册小程序账号，你的登录接口怎么防？
限制微信侧：注册频率/设备指纹/unionid 关联风控；自家侧：登录接口按 IP/openid 限频、新号功能分级（发帖/下单前二次验证）、异常 openid 名单。答题落点：**微信登录只证明"这是个微信号"，不证明"这是个人"**——反作弊永远是业务层责任（呼应 exp-security 的 rate-limit、node-deploy-perf 风控意识）。
**来源**：微信风控官方能力介绍（图盾/天御概念）；业务风控通识
