# mp-openapi 面试题精选

> 共 15 题，覆盖 A 支付链路 / B 分享与增长 / C 设备能力 / D 消息与合规。

## 一、支付链路（A 类）

### 1. 画出小程序支付完整时序，指出"钱货两清"的判定时刻。
端下单→后端建单(待支付)→后端调微信统一下单拿 prepay_id→签名参数回端→requestPayment 收银台→端回调(仅动作完成)→**微信异步通知后端(验签+幂等)=业务成功**→端轮询/收 WebSocket 刷新。判定时刻是"通知落库改状态成功"，不是端 success（呼应 mp-openapi 第一节）。
**来源**：微信支付官方文档《JSAPI/小程序下单》《支付回调通知》

### 2. 用户说"付了钱订单没变化"（掉单），排查路线？
① 查微信侧账单：交易号是否存在/支付时间；② 查通知：回调 URL 是否可达（HTTPS、证书、防抖 15s 内应答）、验签是否失败、handler 是否抛异常；③ 主动查单接口补状态；④ 对账任务兜底。设计上：**回调处理必须幂等**（同一单多次通知只发货一次，用订单状态机+唯一约束）（呼应 exp-rest 幂等）。
**来源**：微信支付官方文档《回调通知失败与重试》；掉单处理社区案例精选

### 3. 为什么金额全链路用"分"？后端数据库怎么存？
整数分杜绝浮点误差（0.1+0.2≠0.3 的 es-number 教训进支付域）与字符串精度问题；DB 用 `BIGINT/INT` 存分（或 DECIMAL 元，二选一不混用），展示层才格式化元——格式化放 wxs/展示端，接口永不传"19.90"字符串（呼应 exp-validation 的类型校验）。
**来源**：微信支付官方文档《金额单位》；金融系统金额存储通识

### 4. 退款需要哪些步骤？用户能在端上退吗？
后端调退款 API（需商户证书/APIv3 私钥）→ 异步退款通知→状态机流转（退款中→成功/失败）。端上"申请退款"只是打到你的客服/售后流程，**不存在前端直接退款 API**——资金操作永远在服务端（呼应 mp-login 的"密钥不下端"原则）。
**来源**：微信支付官方文档《退款申请》

## 二、分享与增长（B 类）

### 5. 分享落地页和正常进入的页面，开发上有什么不同心智？
分享=用户冷启动直落此页：页面必须**参数自治**（onLoad query 拉数据）、**状态兜底**（无登录态可浏览、下单再登录）、**参数防御**（id 被篡改/商品下架的优雅降级）、**归因标记**（scene+分享者 ticket 存渠道表）。`shareTicket`+`wx.checkIsAddedToMyMiniProgram`? 前者用于群成员去重统计（对应 `onShareAppMessage` 的 group 消息）（呼应 mp-communication 面试 12、mp-route 面试 6）。
**来源**：微信小程序官方文档《转发 / shareTicket》；增长归因实践帖

### 6. "分享后才能解锁优惠"会怎样？
属于典型**诱导分享**，违反运营规范：轻则页面驳回、重则封分享能力（朋友圈/群转发全禁）。合规替代：分享得积分之类"不阻塞主流程、奖励后置"也需按最新规范逐条核对——设计评审阶段就把话术送审（呼应 mp-interaction 面试 10）。
**来源**：微信《外部链接及诱导分享行为规范》官方公告

## 三、设备能力（C 类）

### 7. 蓝牙开发为什么"真机测试是硬要求"？
适配器初始化/扫描/连接在 iOS 与 Android 的行为差异（系统弹窗时机、MTU、断连错误码、后台限制）远大于文档承诺；模拟器仅流程联调。健壮写法：状态机管理（未初始化→开启→扫描→连接→服务发现→读写）+ 每步超时 + `onBLEConnectionStateChange` 断线重连（呼应 node-events 的事件驱动状态机）。
**来源**：微信小程序官方文档《蓝牙 */ 低功耗 BLE》；硬件小程序社区踩坑精选

### 8. chooseMedia 拿到的临时文件路径能长期用吗？
不能。临时路径随小程序销毁/一定时限失效，要持久必须 `wx.getFileSystemManager().saveFile` 存到本地用户文件目录（限额 10MB 文件存储），或立即上传服务端换 URL。展示型图片尽快上传后换 CDN 是正解（呼应 mp-storage、exp-upload）。
**来源**：微信小程序官方文档《文件系统 / 临时文件说明》

### 9. 定位返回的坐标和地图上差几十米，为什么？
微信返回 **gcj-02**（国测局加密）；若地图服务用 wgs84（GPS 原始）或 bd-09（百度）需坐标转换，且转换有信息损失与合规要求。工程做法：全链路统一 gcj-02（腾讯/高德小程序 SDK 原生支持），别自己"加偏移凑数"（呼应 node 课程没有直接对应——这是业务数据一致性问题）。
**来源**：微信小程序官方文档《getLocation 坐标类型》；国家测绘标准 gcj-02 通识

## 四、消息与合规（D 类）

### 10. 小程序想做"砍价帮帮"这类裂变，合规的触达手段有哪些？红线在哪？
合规工具箱：一次性订阅消息（用户主动申请）、群待办/小程序商详卡片的正常分享（不带利益胁迫）、企业微信/客服消息（wxopen 客服能力）。红线恒定：利益诱导分享、强制关注、拼运气式弹窗。答题落点：**先讲合规边界再讲玩法**，这是小程序增长岗的真实面试结构（呼应 mp-interaction 面试 10、运营规范）。
**来源**：微信运营规范历史公告合集（裂变治理专章）

### 11. 订阅消息发送失败 43101（用户拒绝）怎么设计业务兜底？
把"订阅结果"当业务数据管：requestSubscribeMessage 的逐模板结果回传后端记录；发送前查订阅余额，不足则降级为"服务通知改站内红点/短信（有手机号才可行）"；长期把高价值动作（支付成功页）设为申请主阵地（呼应 mp-openapi 第四节军规3）。
**来源**：微信支付/订阅消息错误码官方文档；消息触达降级方案设计帖

### 12. requiredPrivateInfos 和 permission 是一回事吗？各管什么？
permission：给**用户看**的用途文案（定位等弹窗里展示，写"为了给附近门店导航"而非"获取你的位置"）；requiredPrivateInfos：**申报接口清单**（getLocation/chooseLocation 等列了才可调，后台审核比对实际调用）——前者是话术层，后者是白名单层；漏申报=API fail，申报超实际=审核问询（呼应 mp-openapi 第五节声明文化、mp-directory）。
**来源**：微信小程序官方文档《接口权限申请与声明》

## 补充（新专题 13-15）

### 13.  画出小程序支付完整时序，指出"钱货两清"的判定时刻，以及为什么需要主动查单。

时序：① 前端选商品→后端建订单（内部记录待支付、生成唯一 out_trade_no、金额分）；② 后端调微信统一下单拿 prepay_id，用签名算法生成前端调起参数（含 paySign）下发；③ 前端 wx.requestPayment 拉起收银台、用户支付；④ 客户端 success（不可信）；⑤ 微信服务器向后端 notify_url 异步推送支付结果——后端验签、核对金额与单号、幂等处理（可能多次推送），确认真正到账、更新订单为已支付，返回成功应答；⑥ 前端支付后或"我的订单"页轮询/查后端拿真实状态再跳转。判定时刻=第⑤步验签通过的异步通知，不是客户端回调。为何还要主动查单：notify 可能因网络/你方服务抖动丢失或延迟，导致"用户付了钱、订单没变"（掉单），所以要有"支付中订单定时主动查微信查单接口"对账兜底 + 掉单补偿。整体原则：以微信为准、异步通知为主、主动查单对账为辅、幂等防重复发货。

微信官方文档《开放能力：支付/订阅消息/分享》；掘金《订阅消息一次性与长期模板工程实践》

### 14.  用户说"付了钱订单没变化"（掉单），你的排查路线是什么？

分层定位：① 客户端——wx.requestPayment 是否真 success、用户是否中途退出/切后台（钱可能已扣但流程没走完）；② 微信→你方 notify——去微信商户/查单接口确认真实支付状态，查 notify_url 是否收到推送、日志有无 5xx/超时/验签失败/金额不符被拒（最常见是通知处理抛异常导致微信重推仍失败或已放弃）；③ 你方内部——notify 处理逻辑是否幂等、是否因并发/重复被错误吞掉、DB 事务是否回滚；④ 前端展示——可能订单其实已更新，只是列表未刷新/onShow 没重拉。修复与预防：主动查单兜底任务 + notify 幂等与重试容忍 + 处理耗时异步化（先应答后处理）、以及"支付中"态的客户端轮询兜底。核心认知：支付是分布式事务，任何一环都可能"看起来没到账"，靠异步通知+主动对账双保险。

SegmentFault《支付回调验签与掉单补偿机制》；知乎《小程序分享裂变的数据追踪设计》

### 15.  requiredPrivateInfos、permission、隐私协议三者各管什么？调用定位/订阅消息前置清单？

① permission（app.json）：声明"地图/定位等接口的授权文案与用途说明"，是给用户看的授权弹窗描述；② requiredPrivateInfos（app.json）：显式列出会用到的"涉及用户隐私的接口"（如 getLocation/chooseAddress），不在清单里调用会被直接拒绝——这是平台"接口级白名单"；③ 用户隐私保护指引（mp 后台配置）+ 运行时的隐私同意（__usePrivacyCheck__/隐私弹窗）：决定"用户是否已同意你收集"，未同意前隐私接口即便声明了也可能被拦。以 wx.getLocation 为例的前置：后台配置并声明 requiredPrivateInfos、app.json permission 写明用途、通过隐私同意、申请到对应接口权限（部分类目/主体受限）、真机弹授权用户点允许。缺一即"开发能跑、体验版/线上失败"。订阅消息则要先在后台选模板、前端 requestSubscribeMessage 在用户主动行为链路上申请（一次性订阅一次授权只能发一条），配额来自用户点击累加。

CSDN《地理位置授权合规与隐私协议改造清单》；InfoQ《开放能力审核被拒的五类常见原因》
