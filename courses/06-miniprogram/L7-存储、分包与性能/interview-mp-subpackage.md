# mp-subpackage 面试题精选

> 共 12 题，覆盖 A 规则与限制 / B 策略设计 / C 独立分包深水区 / D 与 Web 拆包对照。

## 一、规则与限制（A 类）

### 1. 小程序包体积的限制体系？
整包（所有分包总和）上限 30M、**单个分包/主包 ≤2M**（历史数字，官方多次提升总量，答题报"主包 2M、总包数十 M 以最新文档为准"）；超限无法上传。tabBar 页与启动页必须在主包；分包不能互相引用（呼应 mp-subpackage 第一节）。
**来源**：微信小程序官方文档《分包加载 > 使用限制》

### 2. 分包的 pages 路径怎么写？root 是什么？
`subPackages: [{ root: 'packageA', pages: ['order/list'] }]` → 实际文件 `packageA/order/list.*`，跳转 url `/packageA/order/list`。root 是分包目录前缀，pages 内相对 root（呼应 mp-subpackage 第一节代码块）。
**来源**：微信小程序官方文档《app.json subPackages》

### 3. 分包里能放组件、工具、静态资源吗？各有什么讲究？
都能：分包组件随包走（usingComponents 相对路径）、utils 可被本包 require；静态资源放分包仅在"该包页面独用"时才不浪费主包额度；但**跨包共享一律上收主包或外置 CDN**（呼应 mp-subpackage 第三、四节）。
**来源**：微信小程序官方文档；社区分包资源组织实践

## 二、策略设计（B 类）

### 4. 你接手一个主包 1.9M 快爆仓的项目，瘦身动作按什么顺序做？
① 画像：工具看主包构成（大头往往是图片/字体/moment 类重库）；② 静态资源全外置 CDN（收益最快）；③ 非启动页迁分包（任务流切法）；④ 全局组件/utils 审计（被 1 页用的挪出全局）；⑤ 三方库换轻量版（如 moment→date-fns 按需）；⑥ 建 CI 包体红线防回潮（呼应 10-vite 产物分析、exp-deploy 门禁）。
**来源**：小程序包瘦身实战社区精选；Web bundle 瘦身方法论平移

### 5. preloadRule 配置在什么场景收益最大？配错有什么副作用？
收益最大："入口页稳定 + 下一步高度确定"（首页→下单、列表→详情同包）；副作用：预下载占用户带宽与流量（蜂窝全开 network:all 要克制）、包多且齐预载会挤占交互期网络/IO——预下载列表是产品决策不是技术默认（呼应 mp-subpackage 第二节②、vite-splitting 的 prefetch 意图）。
**来源**：微信小程序官方文档《preloadRule》

### 6. 什么页面适合做"独立分包"？给出三个业务画像。
① 扫码即达的活动/抽奖页（分享裂变直落）；② 硬件配对引导页（扫蓝牙设备码进来）；③ 客服/售后自助页（服务通知点开）。共性：**入口在外部、到达路径绕过首页、要求极限首开**；且能接受"公共代码冗余一份"（呼应 mp-subpackage 第二节③）。
**来源**：微信小程序官方文档《独立分包》；社区场景案例

## 三、独立分包深水区（C 类）

### 7. 独立分包为什么禁止 require 主包代码？微信在技术上省了什么？
直落独立分包时**主包尚未（也不需要）下载注入**——任何对主包模块/样式的静态依赖都会悬空。省掉的是"启动完整性校验与主包注入"，代价是公共逻辑冗余（可用"基础库级共享+构建期复制"化解）（呼应 mp-subpackage 第二节③）。
**来源**：微信小程序官方文档《独立分包注意事项》

### 8. 独立分包页里用户点进主流程，加载模型怎么变？
navigateTo/switchTab 触发主包下载+注入后进入普通页——用户视角"下一步稍慢半拍"，设计预期：独立包页内动作按钮加轻量 loading；重要主流程可 `wx.loadSubPackage` 提前预热相邻包（呼应 mp-performance 的"等待要有反馈"）。
**来源**：微信小程序官方文档《loadSubPackage》

### 9. 分包异步化（分包组件占位）解决什么？怎么用？
解决"主包页面想复用某个分包大组件（如图表/地图业务卡）但不想把组件拖回主包"：usingComponents 指向分包组件 + `componentPlaceholder` 给占位自定义标签，组件异步到位前渲染占位。本质=小程序版 React.lazy+Suspense（呼应 mp-subpackage 第二节末、react-async-suspense 概念）。
**来源**：微信小程序官方文档《分包异步化》

## 四、与 Web 拆包对照（D 类）

### 10. 小程序分包 vs Vite 的 manualChunks/动态 import，同与不同？
同：都按"进入时机"切资源、都追求首载最小、都有"共享依赖上浮"处理（webpack runtime/主包）。不同：小程序切分是**官方配置的物理包**（平台托管下载/缓存/校验），粒度受 2M 硬顶约束、不能运行时任意拆；Web 是 CDN+浏览器缓存，粒度自由但需自己管缓存失效（呼应 vite-splitting、react-performance 的 lazy）。
**来源**：Vite/Rollup 官方文档 Code Splitting；微信分包文档对照

### 11. 跨端框架（Taro/uni）里分包怎么写？和原生差异？
配置入口不同（Taro 用 app.config 的 subPackages+pages 前缀、uni 用 pages.json 的同名机制+条件编译），**运行时模型与原生完全一致**（编译产物就是原生分包）。面试加分点：说明"跨端不改变包体策略，只改变书写方式"（呼应 mp-framework、mp-subpackage 第四节事故5）。
**来源**：Taro 官方文档《分包》；uni-app 官方文档《subPackages》

### 12. 包体之外，启动耗时还有哪些大头？分包为什么不是万能药？
官方启动三段：代码包下载、注入运行框架、首页渲染（setData+首绘）。分包只砍第一段；若慢在"首页同步 getApp 读大缓存、onLoad 串行请求、超大 initial setData"，得回到 mp-storage/mp-setdata/mp-performance 的组合拳（呼应 mp-performance 第一节链路）。
**来源**：小程序性能指南《启动流程》；体验评分指标文档
