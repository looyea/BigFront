## 第一段 · 读代码找 Bug / 找问题（10 小题）

```jsx

```

**2.** uni-app 工程把 `uni.setTabBarItem` 的代码写在 `// #ifdef APP-PLUS` 块里，H5 与微信小程序端调用报错，为什么？条件编译块该配几个？

**3.** 云函数代码指出两个问题（安全/职责各一）：
```js
// 端直接调 this.db.collection('user').update(...) 改余额字段
// 云函数只做：await db.collection('order').add({ data: event })   // event 原样入库
```

**4.** 云开发安全规则写成 `"read": true, "write": "doc._openid == auth.openid"`，说出这条规则暴露了什么、保住了什么。

**5.** 体验版一切正常，提审新版审核员反馈"首页一直转圈"，而用户也偶现——从"环境配置"角度给出两个最可能原因。

**6.** 团队把上传私钥 `private.key` 提交进了 Git 仓库并打了 tag。列出即刻处置三步与长期规矩一条。

**7.** 小程序端 `console.log(err)` 的报错想捞出来分析，为什么捞不到？端上缺了什么体系？

**8.** 审核驳回："用户仅浏览场景强制授权手机号登录。"对照懒登录原则，指出代码里最可能出事的位置（App.onLaunch 或首页 onLoad）并给出改造方案。

**9.** Taro 页面每次 setState 都卡，性能面板发现 setData 传输远超预期。用"Taro 数据绑定粒度 + mp-setdata 成本模型"解释这个放大效应，给两条缓解。

**10.** 上线 1.2.0 后发现新接口字段 `discountType` 老逻辑读不懂，于是回退到 1.1.0，结果**新版写入的数据把老版页面搞崩**。这暴露了发布流程里哪个约束被忽略了？

## 第二段 · 手写编程（5 小题）

**11.** 用 Taro（React 语法）改写一个原生的"计数页"：Page({data:{n}, plus(){...}}) → 函数组件 + useState + Taro.showToast；并标注：哪个 Hook 对应 onLoad、哪个对应 onShow（呼应 mp-lifecycle）。

**12.** 给 uni-app 写一段"手机号授权"双端适配：`#ifdef MP-WEIXIN` 用 getPhoneNumber 按钮、`#ifdef H5` 用短信验证码表单，公共部分抽出 `bindPhone(code?)` service。30 行内。

**13.** 写一个云函数 `feedback`：入参校验（content 长度/敏感词走 `cloud.openapi.msgSecCheck`）→ 落库（_openid 自动）→ 返回 {ok}；并写出对应的端上调用与失败提示（复用 feedback utils，呼应 L3 作业 20 的封装）。

**14.** 实现最小"配置开关"模块：`flags.js` 冷启动拉 `/config`（带 ETag 缓存）、merge Storage 旧值、暴露 `flags.enabled('newCart')`；页面示例用它包一层新旧双渲染路径。写 25 行内核心。

**15.** 用 miniprogram-ci 思路写发布脚本骨架（node 脚本即可，无需真密钥）：读取 git tag 作版本号、CHANGELOG 首段作描述、执行 upload 并打印结果；说明该脚本挂在 CI 的哪个阶段、密钥放哪。
